> 日期：2026-08-11
> 状态：已确认，待实施

## 1. 背景与目标

博主「沉舟」为后端求职者（简历项目：自研 C 语言网关 Nexus Gateway），计划搭建个人技术博客，**核心目的是写在简历上给面试官看**。

**成功标准：**

- 简历放上博客链接后，面试官打开能看到专业、完整的技术博客
- 博客展示开发日志、历史项目复盘、面试经验三大类内容
- 发文章流程足够简单：写 Markdown → push → 自动上线

**内容计划（首批及后续）：**

- 关于页 / 简历页先行
- Nexus Gateway 项目复盘（重点，简历项目）
- 面试经验沉淀
- 日常开发日志

## 2. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 站点生成器 | Hugo | Go 编写、构建快、主题丰富，与后端求职方向契合 |
| 主题 | PaperMod | 极简开发者风、自带搜索/RSS/暗色模式、可配置定制 |
| 部署 | GitHub Pages + GitHub Actions | 免费、push 即部署；源码仓库本身是简历展示 |
| 域名 | `https://chenzhou0071.github.io`（免费默认） | 零成本，随时可升级自定义域名 |
| 评论 | giscus（GitHub Discussions） | 零服务器、GitHub 账号可评论 |
| 内容语言 | 中文写作，分类/标签 URL 用英文 slug | URL 整洁，面试官阅读无压力 |

## 3. 架构与部署流程

```
写作（本地）: content/posts/*.md → git push
    ↓
GitHub 仓库（chenzhou0071.github.io）
    ├── 站点源码 + 文章（简历展示）
    └── GitHub Actions 工作流（push 自动触发）
    ↓ hugo build
GitHub Pages: https://chenzhou0071.github.io
```

**部署规则：**

- 每次 push 到默认分支触发 Actions 构建并发布 Pages
- 本地不强制安装 Hugo（构建在 Actions 完成），但建议安装用于本地预览
- 使用官方 actions：`actions/checkout@v4`、`actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`

## 4. 站点结构与内容组织

```
舟上码途 —— 沉舟的技术手记
├── 首页            文章列表（时间倒序）
├── 归档
│   ├── 分类: project-review(项目复盘) / interview(面试经验) / dev-log(开发日志)
│   └── 标签: c语言 / 网关 / 并发 / 网络编程 / 面经 / 简历 ...
├── 关于            自我介绍、技能栈、联系方式
├── 简历            在线简历页 + PDF 下载
└── 搜索            站内全文搜索（PaperMod 自带）
```

**URL 结构**：`/posts/<分类>/<文章slug>/`

**分类固定三个，稳定不变**；标签自由增长。

**关于页**：技术栈、方向、GitHub/邮箱联系方式、博客定位一句话。

**简历页**：在线简历摘要 + 简历 PDF（存仓库中，走 git 更新留痕）。

## 5. 功能清单

**PaperMod 自带（配置即用）：**

- 暗色/亮色模式切换（跟随系统）
- 站内全文搜索（纯前端索引）
- RSS（`/index.xml`）
- 标签 + 分类归档页
- 代码高亮（支持 C 代码）
- 阅读进度条、TOC 目录

**个性化定制（不修改主题源码，用配置 + 模板覆盖）：**

- 头像/站点 Logo：二次元风格图，放 `static/` 目录，可随时替换
- 404 页面：重写 `layouts/404.html`，二次元梗图 + 俏皮话 + 返回首页链接
- favicon：二次元风格小图

**giscus 评论：**

- 基于 GitHub Discussions，零服务器成本
- 一次性配置：仓库开启 Discussions + 安装 giscus 应用 → 配置写入站点配置
- 未配置完成前评论框不显示，不影响其他功能

## 6. 写作与发布工作流

**日常写作（唯一手动流程）：**

```
hugo new posts/<分类>/<slug>.md   # 生成模板
# 写内容，未完成时保留 draft: true（本地可见、线上不发布）
hugo server                        # 本地预览（可选）
git push                           # 自动构建部署
```

**首次上线流程（实施阶段完成）：**

1. 初始化 Hugo 站点，引入 PaperMod 主题
2. 完成全部站点配置（标题、导航、搜索、暗色模式等）
3. 建分类/标签/关于/简历/404 骨架
4. 生成首批示例文章（Nexus Gateway 复盘、面经模板、开发日志模板）
5. 配置 GitHub Actions 工作流 + giscus 接入
6. 创建 GitHub 仓库并关联，首次 push 上线

## 7. 错误处理预案

| 场景 | 处理 |
|------|------|
| Actions 构建失败 | 查看 Actions 日志（多为 YAML/hugo 版本问题），修复后重新 push |
| 本地未装 Hugo | 不影响发布，仅影响本地预览；安装后即可 |
| giscus 未配置 | 评论区不显示，其余功能不受影响 |
| 半成品文章 | `draft: true` 标记，完成后再发布 |

## 8. 测试与验收

- 本地 `hugo server` 预览全部页面：首页、文章页、归档、搜索、404、关于、简历
- 移动端排版检查（面试官可能手机访问）
- 部署后链接检查，无死链

## 9. 明确不做的事（YAGNI）

- 不购买自定义域名（后续可平滑升级）
- 不 fork 魔改主题源码
- 不做后端、不用数据库、无登录体系
- 不做访问统计/SEO 优化（后续需要可加，如 Google Analytics、sitemap）
- 不追求评论区热闹，仅保证功能完整
