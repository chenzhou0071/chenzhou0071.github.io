## 项目背景

写什么：为什么做这个项目（学习动机 / 求职需要 / 解决什么问题）、目标是什么、技术选型及原因。

参考要点：
- 选型要说"为什么不用框架/库"，体现对底层机制的理解；
- 目标要具体（如"把一条完整链路做深"），不要"功能大而全"。

## 总体架构

写什么：架构模型（多进程/多线程/事件驱动等）、模块划分、一次请求的数据流。

参考要点：
- 用 ASCII 图示画出架构与数据流（如 Master-Worker 结构、请求状态流转）；
- 点出设计亮点：为什么这样分模块、状态机怎么分层。

## 关键技术决策

写什么：3-6 个关键取舍，每个决策讲清楚"选项 → 为什么选这个 → 代价是什么"。

参考要点：
- 用对比结构（如"事件驱动 vs 多线程 per-connection"）；
- 贴关键代码片段（10 行以内），不要大段贴代码；
- 可以做一个"内核提供 vs 自己实现"的对照表，突出含金量。

## 踩坑记录

写什么：最有价值的 2-4 个故障排查，按「现象 → 排查 → 根因 → 修复」四段式组织。

参考要点：
- 现象要具体（报错信息/压测数据）；
- 根因分析要深入一层（为什么会出现这个 bug）；
- 修复代码 + 修复后的验证结果（如"连续多轮热重启全部正常"）；
- 结尾写一句可迁移的教训。

## 性能与效果

写什么：压测环境、数据表格、与主流实现（如 Nginx）对比、已知局限。

参考要点：
- 数据要真实（环境、参数、指标、p99 等）；
- 主动列出已知局限和改进方向——比只说优点更可信。

## 复盘与收获

写什么：做完后认知上的变化（从"概念"到"机制"）、排障方法论、工程意识、后续方向。

参考要点：
- 面试官最想听的部分，多写"认知变化"而不是"做了什么"；
- 可以分点写：理解质变 / 方法论 / 工程意识 / 后续方向。
